# 给新工作区建项目册

## 什么时候用

会话开头的注入块里出现这两行之一：

```
总册根：C:\Users\<你>\.memory    本项目册根：（无，本工作区未建项目册）
本工作区还没有项目册。如果这里会长期干活（不只是临时看个文件），跑 `/memory-init` 建册：它会先问你三个问题，不会静默建。
```

就是这个场景。**但不要立刻建。**

## 第一步：先过排除表

技术性排除，**不判断值不值得建**——那是第二步的事。命中就一句话说明，不建、也不问。

| 排除 | 为什么 |
| --- | --- |
| home 目录、盘根（`C:\`、`E:\`）、系统目录 | 不是项目。建了就是垃圾，还会被 cwd 向上查找误命中 |
| `~/.memory` 本身 | 那是总册，不是项目册 |
| 已经在某个项目册内部 | cwd 向上已经能找到 `_meta.md`，注入里已经有了 |

`init --project` 自带这套检查（`excluded_reason`），但它**只拦命令，不替你解释**。先看，再跑。

## 第二步：判断三种状态

| 状态 | 判据 | 做什么 |
| --- | --- | --- |
| **完全没有** | 没有 `<工作区>/.memory/` | 走第三步，问三个问题 |
| **半建** | 有 `.memory/`，但没有 `_meta.md` | **不要往上盖。** 报出里面已有什么，让用户选：手工补 `_meta.md`，还是删掉重来 |
| **缺本 agent 日志** | 有 `_meta.md`，缺 `log/<当前 agent>/` | **不问问题**，直接 `mkdir -p`，补一行日志就完事 |

**为什么半建不自动补**：`.memory/` 里已经有东西，说明有人在这块做过决定。静默补 `_meta.md` 会把「不完整的册子」变成「看起来完整的册子」——比缺着更危险。

## 第三步：三问，一次问完

每个问题给**至少 3 个具体选项 + 一个「其他」**，标推荐度（★★★ / ★★ / ★），星数后跟理由。

| # | 问什么 | 选项从哪来 | 落到哪 |
| --- | --- | --- | --- |
| 1 | **这项目属于哪类？** | 扫目录动态推荐：看到 `package.json` / `pyproject.toml` → ★★★ `engineering`；看到 `.docx` / 大量 `.md` 章节 → `writing`；看到 `.bib` / `paper` / `experiment` → `research` | `kind`（= `shared/playbooks/` 下的目录名） |
| 2 | **一句话定位？** | 不问选项，直接要一句话（**≤40 字**，超了 checkup 会提示） | `_meta.md` 的 `## 定位` |
| 3 | **现在什么状态？** | ★★★ 进行中 / ★★ 待启动 / ★ 搁置 | `_meta.md` 的 `status` |

**第 1 问的 `kind` 不能猜着填**：它的取值必须和 `shared/playbooks/` 下真实存在的目录一一对应。不确定就先跑 `python memory.py status` 看有哪些。填错的后果不是报错，是**静默不注入方法论**。

**第 2 问是事实型，不硬凑选项**：只有用户知道这项目是什么。

## 第四步：跑命令

```bash
python <插件根>/core/memory.py init --project <工作区路径> \
  --id <id> --title "<标题>" --kind <领域>
```

它一次做完这些（2026-10-27 起）：

- 建 `.memory/{_meta.md,index.md,core.md}` + `log/<当前 agent>/`
- 项目册 `git init` + 首次提交
- 工作区是 git 仓库时，往 `.gitignore` 加 `.memory/`（不加就是嵌套仓库，主库只留一个灰格子）
- 记建册日志，末尾 `提炼：无（建册）`
- 登记 `workspaces.json` + 同步总索引三张表
- 跑一次注入验证

参数：`--id` 省略用目录名 slug 化（只允许小写字母、数字、连字符）；`--title` 省略用目录名；**`--kind` 省略等于没配**——不设默认值是故意的，见上。

## 第五步：看验证结果（CLI 已经跑过）

`init` 最后会打一行「自动验证：注入渲染通过，标题进得去」。通过就完事。

没过的话它会把命令打出来：

```bash
python <插件根>/core/render.py --dry --cwd "<工作区路径>"
```

对着输出确认三件事，缺一件就是没建对：

1. 有 `### 项目册 · <标题>（进行中）` —— 定位成功
2. 有 `### 方法论路由 · ...` —— `kind` 接上了
3. 没有 `⚠️` 告警 —— 没有缺必需文件

**建册日志不要再写一遍**，CLI 已经写了；有实际结论要补时追加在后面。

## 不做的事

- **不静默建册。** 所有用户工作区默认建册，但必须问一句。判断「值不值得建」需要意图，AI 只看得见目录。
- **不建空子文件。** 记录模板（论文笔记、实验记录这类）等真有内容再建。
- **不在别人的项目里建。** 工作区不是用户让你碰的地方，就别碰。
- **建完不改 `status`。** 那是用户的字段，只在他说「这个搁置了」时改。
