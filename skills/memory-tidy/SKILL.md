# 整理记忆库

## 第一步：体检

跑 `python <插件根>/core/memory.py checkup`，拿到问题清单和归档候选。

## 第二步：分两类

| 类 | 包含 | 处理 |
| --- | --- | --- |
| 能自动修的 | 索引漂移、缺字段、空话 `summary`、骨架不全 | 列清单 → 直接修 |
| 要用户判断的 | 重复条目、归档候选、互相矛盾的结论 | 逐条问 |

**自动修之前也要列清单**，让用户知道你要动什么。

## 第三步：自动修

| 问题 | 怎么修 |
| --- | --- |
| 索引漂移 | 跑 `index --write` |
| 缺 `summary` | 按「必须含具体名词」补，补不出就问用户 |
| 空话 `summary` | 改成具体名词，改不出标 `（待补）` |
| 缺字段 | 补 `when` / `owner`，补不出就问 |
| 骨架不全 | 补 `_meta.md` 或 `index.md` |

修完报告改了什么，一行一条。

## 第四步：逐条问

每条给 3 个选项 + 推荐度（★★★ / ★★ / ★），星数后跟理由。

**归档候选**

- ★★★ 保留 — 兜底信息，很少被读但违反了会出事
- ★★ 归档 — 移到 `archive/<册子或主题>/`，主文件留一行指针
- ★ 删掉 — 不推荐，删了没法回溯为什么改

**重复条目**

- ★★★ 合并 — 保留信息更全的那条，另一条标失效日期
- ★★ 保留两条 — 如果是不同场景下的不同结论
- ★ 删掉一条 — 不推荐

**矛盾结论**

让用户裁决，**不自己选**。说明两边分别是什么、什么时候写的、分别来自哪里。用户不表态就跳过，记进日志等下次。

## 第五步：收尾

1. 跑 `index --write`
2. `git -C ~/.memory add <改过的路径> && git commit -m "tidy: <一句话>"`（别用 `-A`，会把别的 agent 的在途修改卷进来）
3. 输出

## 输出

一张表：改了什么 / 为什么 / 跳过了什么。不超过 10 行。

不写「整理完成，希望对您有帮助」这类话。
