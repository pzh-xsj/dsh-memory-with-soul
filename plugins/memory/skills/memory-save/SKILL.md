# 保存记忆

用户要沉淀当前对话。**五步不许跳**，跳了就会漏。

## 第零步：先确定写进哪本册子

两级结构，别搞混：

| 册子 | 路径 | 装什么 |
| --- | --- | --- |
| **项目册** | `<workspace>/.memory/`（从 cwd 向上找 `_meta.md`） | 只对这一部小说 / 这一个工程成立的东西 |
| **总册** | `~/.memory/` | 跨项目、跨领域、关于主人本人的东西 |

判定顺序（越具体的作用域优先）：

1. 换一个同类实例（另一本小说 / 另一个工程）还成立吗？→ 不成立，进项目册
2. 换一个领域（小说 ↔ 科研 ↔ 工程）还成立吗？→ 不成立，进 `shared/playbooks/<领域>/<类型>.md`
3. 换一个人用还成立吗？→ 不成立，进 `shared/user/preferences.md`
4. 只对这个角色成立 → `roles/<当前角色>/SOUL.md`（先看 `python core/memory.py roles` 确认这个 agent 读哪张卡）
   （当前 agent 的 id 形如 `moxie-wb` / `moxie-dsh`，注入内容第一行就写着。别猜。）
5. 都不是 → `shared/playbooks/general/<类型>.md`（**`general/` 目录现在还不存在**，按需建；空目录 git 不跟踪，建了只会让人以为「这块有人管了」）

宽层只留指针，不重复正文。

## 第一步：提取候选

从这次对话里挑出值得跨会话保留的东西，列成清单：

- 只挑「下次还会用到」的：稳定事实、偏好、决定、结论、踩过的坑、改过的设定
- 不挑：一次性闲聊、临时状态、能从当前对话直接看到的
- 每条写成**一句独立的话**，脱离上下文也读得懂

**列完先给用户看，不要直接写。**

## 第二步：确认归属

每条判断进哪本册子的哪个文件。**有歧义时给选项，不自己猜。**

格式：3 个具体候选 + 「其他」+ 推荐度（★★★ / ★★ / ★），星数后跟理由。

示例（群星项目）：

- ★★★ `world.md` — 手环规则本来就归这里
- ★★ `characters.md` — 如果这条其实是人物动机
- ★ `~/.memory/shared/playbooks/novel/method.md` — 如果它跨作品通用

## 第三步：冲突判定

对每条，和目标文件里已有内容比对，四选一：

| 判定 | 什么情况 | 动作 |
| --- | --- | --- |
| ADD | 新事实，不冲突 | 新增，行尾带 `（源：YYYY-MM-DD）` |
| UPDATE | 同一件事的新版本 | 改原行，旧值用 ~~删除线~~ 保留并标失效日期 |
| DELETE | 新结论推翻旧结论 | 旧行标 `~~已失效 YYYY-MM-DD~~`，不物理删除 |
| NOOP | 价值不大、重复、临时 | 不写。**大部分属于这一类** |

判不准选 NOOP，在日志记一笔，等它第二次出现再处理。

## 第四步：提炼并写入

**顺序不能反：先提炼，再写标记。** 先写标记等于给自己发一张「已完成」的假证明。

1. 读当天日志的 `## 结论` 段，逐条判断归属（这一步是判断，不是抄写）
2. 跑 `git -C <册子根> status --porcelain`，目标文件有未提交改动就先读再合并，**不覆盖用户的句子**
3. 改目标文件
4. 更新项目册 `index.md`（当前状态、最近变更）
5. 日志末尾补一行：
   - 提炼了 → `提炼：world.md, characters.md`
   - 判断后确实不用提炼 → `提炼：无（理由）`
   - **只写「无」不合格**，和没写分不出来
6. 总册有改动就跑 `python <插件根>/core/memory.py index --write`

## 第五步：提交

```
git -C <册子根> add <你改过的文件路径> && git commit -m "save: <一句话说清写了什么>"
```

**不要用 `git add -A`**：记忆库可能同时有另一个 agent 在写，`-A` 会把它的半成品一起提交。
项目册是独立 git 仓库，和总册分开提交。

## 输出

一句话：**写了什么、进了哪里、旧条目怎么处理的**。

不写长篇总结，不复述流程，不说「希望对您有帮助」。
